# RouterDebugger

Безопасная веб-панель для управления роутером **TP-Link WR740N** (прошивка
`3.13.2`, аппарат v4) через интернет. Сервер ходит на роутер по локалке с
`admin:admin`, а тебя пускает только по **отдельному сложному логину/паролю**
с защитой от перебора. Разворачивается в Coolify, HTTPS навешивает сам Coolify.

```
[ Интернет ] --HTTPS--> [ Coolify/Traefik ] --> [ RouterDebugger ] --HTTP+Basic--> [ 192.168.0.1:8080 ]
                                                   (твой логин/пароль)              (admin:admin, только LAN)
```

Роутер **не** выставляется в интернет напрямую — наружу смотрит только эта
панель со своей авторизацией.

## Что умеет

Покрыты **все 44 страницы** родной веб-морды WR740N — слева сайдбар с деревом
меню как у роутера, справа единый красивый интерфейс. Разделы:

| Раздел | Страницы |
|---|---|
| **Состояние** | Обзор: прошивка, аптайм, WAN, LAN, Wi-Fi, трафик |
| **Сеть** | WAN (PPPoE), Клонирование MAC, LAN, Режим LAN/IPTV |
| **Беспроводной режим** | Настройки, Защита (пароль), Фильтрация MAC, Доп. настройки, Статистика |
| **DHCP** | Настройки, Список клиентов, Резервирование адресов |
| **Переадресация** | Виртуальные серверы, Port Triggering, DMZ, UPnP |
| **Защита** | Базовая, Расширенная (DoS), Локальное/Удалённое управление |
| **Родительский контроль** | Правила |
| **Контроль доступа** | Правила, Узлы, Цели, Расписания |
| **Маршрутизация** | Статические маршруты, Таблица маршрутизации |
| **Контроль ПС (QoS)** | Общие настройки, Правила |
| **Привязка IP/MAC** | Настройки, ARP-таблица |
| **Динамический DNS** | DDNS |
| **Системные инструменты** | Время, Диагностика (ping/tracert), Прошивка⚠️, Сброс⚠️, Бэкап/восстановление⚠️, Перезагрузка, Пароль роутера⚠️, Журнал, Статистика |
| **Эксперт** | Сырой GET к `/userRpm/*` — escape-hatch на всякий случай |

Особые операции реализованы аккуратно: **смена пароля роутера** сразу обновляет
креды сервера; **прошивка/восстановление** — multipart-загрузка файла; **сброс**
требует ввод подтверждения; везде — предупреждения о последствиях.

### Архитектура движка

Большинство страниц однотипны (данные в JS-массивах + форма), поэтому каждая
описана **декларативно** (`PageSpec`), а универсальный движок (`engine.py`)
читает/пишет её без отдельного кода на страницу. Декларации лежат в
`app/pages_data.json` (восстановлены реверс-инжинирингом реальных страниц).
Особые страницы (прошивка, бэкап, сброс, пароль, WPS, диагностика) — отдельные
обработчики.

## Безопасность

- Вход только по `APP_USERNAME` / `APP_PASSWORD` (сравнение в постоянном времени).
- Анти-брутфорс: после N неудач — блокировка по IP (учитывает `X-Forwarded-For`).
- Сессия в подписанной cookie (`HttpOnly`, `SameSite=Strict`, `Secure` за HTTPS).
- CSRF-токен на все изменяющие запросы.
- Креды роутера (`admin:admin`) живут только на сервере и наружу не отдаются.

## Деплой в Coolify

1. Запушь репозиторий и создай в Coolify ресурс **Docker Compose** из него
   (либо **Dockerfile**-ресурс — `Dockerfile` тоже самодостаточный).
2. Задай переменные окружения (см. `.env.example`). Обязательно:
   - `APP_USERNAME`, `APP_PASSWORD` — длинный пароль (16+ символов);
   - `SECRET_KEY` — сгенерируй: `python -c "import secrets; print(secrets.token_hex(32))"`.
3. Привяжи домен — Coolify сам выпустит сертификат (HTTPS).
4. Внутренний порт сервиса — **8000**.
5. **Сетевая доступность роутера.** Контейнеру нужно достучаться до
   `192.168.0.1:8080`. Если сервер Coolify в той же LAN — обычно работает сразу.
   Если контейнер не видит роутер, в `docker-compose.yml` включи
   `network_mode: host`.

## Локальный запуск (для теста)

```bash
python -m venv .venv && . .venv/Scripts/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export APP_USERNAME=admin APP_PASSWORD=test12345 COOKIE_SECURE=false
export ROUTER_URL=http://192.168.0.1:8080
uvicorn app.main:app --reload --port 8000
# открой http://127.0.0.1:8000
```

## Под другой роутер / прошивку

Разбор страниц завязан на конкретный формат JS-массивов прошивки WR740N v4
(`app/router_client.py`). На другой модели/прошивке индексы массивов и имена
полей форм могут отличаться — правь парсеры и методы записи в `router_client.py`.
Папка `_probe/` (в `.gitignore`) — это сырые дампы страниц роутера, по которым
восстановлена структура; пригодятся при адаптации.

## Структура

```
app/
  config.py          # конфиг из ENV
  router_client.py   # клиент к роутеру: парсер JS-массивов + чтение/запись + особые операции
  pagespec.py        # формат PageSpec + дерево меню (MENU)
  engine.py          # универсальный движок чтения/записи форм и списков
  registry.py        # реестр страниц (ручные + загрузка pages_data.json)
  pages_data.json    # запечённые декларации страниц (источник истины, shippable)
  security.py        # логин, рейт-лимит, CSRF
  main.py            # FastAPI: меню, /api/page/*, особые операции, custom-эндпоинты
templates/           # login.html, index.html (каркас с сайдбаром)
static/              # styles.css, app.js (сайдбар + генеративные рендеры + компоненты)
tools/
  build_pages.py     # дев: _probe/desc/*.json -> app/pages_data.json
  devserver.py       # дев-запуск для preview/отладки
Dockerfile, docker-compose.yml, .env.example
```

`_probe/` (в `.gitignore`) — сырые дампы страниц роутера и дескрипторы, по которым
восстановлены декларации. Под другую модель/прошивку: пересними страницы и
перегенерируй `pages_data.json`.

## Дисклеймер

Проект сделан под конкретную модель/прошивку (**TL-WR740N v4, 3.13.2**) и
взаимодействует с её недокументированным веб-интерфейсом. Используй на свой
страх и риск, на своём оборудовании. Не выставляй панель в интернет без надёжного
пароля и HTTPS. Операции прошивки/восстановления/сброса необратимы.
